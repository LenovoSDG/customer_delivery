# 体验审查与验收（2026-11-25）

基于 `codex/windows1.14` 的 `c618e32`，在 `codex/experience-first` 修复。沿用紫灰视觉与 Windows 能力，围绕“复杂留给系统”收紧主流程。

| 原则 | 落地行为 |
| --- | --- |
| 系统能判断的不留给用户 | 导入后自动提取需求；检测设备能力；提供真实模型目录；质检检查前置条件 |
| 此刻没用的不出现 | 原文、检查规范、演练时长/重点、语音参数按需展开；闲置演练按钮隐藏；移除未接入的机器人入口 |
| 能替人做的直接做 | 自动保存规范与草稿；确认需求生成交付任务；截图上传后启动识别 |
| 同一件事处处一样 | 统一主操作颜色、字体、状态、取消行为、通用本地/自定义 API 命名 |
| 按下去有回应，再按能收回 | 分析与质检可取消，后端收到断连会终止对应模型调用；需求确认可撤回；移除可撤销 |
| 不打断手头的事 | 内联修改与提示代替 alert/prompt；后台检查保留已有报告；不会用规则演示覆盖模型失败 |
| 常用易做，丢东西难误碰 | 演示项目独立创建；移除需求保留关联任务和材料；项目读取失败禁止写回；模型测试不保存配置 |
| 界面自己说明自己 | 保存/加载/失败恢复提示，明确附件不参加文字质检、模型未完成及音频去向 |

客户事实、交付承诺和识别来源仍需人工核对。系统不会自动把 AI 候选当作已确认需求。

## 已实际操作验证

- 浏览器创建项目、空必填表单取消、多个项目列表与客户搜索、确认/撤回需求、移除/撤销、导入文档、切换项目。
- 导入 3 条合成客户沟通，由当前自定义 API `glm-5.2` 自动整理为 3 项需求。人工确认后上传合成汇报稿。
- 真实质检指出管理员手册缺失，以及 92% 指标缺少统计周期、样本数和来源。取消、重试均操作验证。发现并修复“仅返回 ** 仍显示完成”的缺陷。
- 使用模型目录接口读到 43 个模型；连接测试成功，未保存草稿修改；关闭后再打开仍为原模型。
- 中文合成录音通过文件选择器导入，本机 Whisper 输出“本次交付需要管理员操作手册,效率指标必须注明统计周期和数据来源。”，随后自动进入需求整理。
- 真实模型完成文字演练，两次回复约 6.2 秒、5.7 秒；浏览器自动朗读回调到达 ended。没有录制环境声音。
- 刷新后对话、反馈和未发送草稿恢复；恢复时暂停演练，麦克风不自动开启。
- 检查 390×844 与 1280×900 布局；移动端主导航可横向滚动，正文没有页面级横向溢出，当前可见内容无小于 11px 的文字。
